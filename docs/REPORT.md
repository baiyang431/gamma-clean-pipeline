# 实现与运行报告

## 实现思路

程序按“读取规则和数据、检查结构、逐条清洗、去重、输出”的顺序执行。JSON 规则与数据分开放置，字段约束和去重列由配置指定。

命令行入口负责参数和退出码；核心模块分别处理配置检查、字段转换、逐条清洗和文件读写。`ser` 编码 CSV 和剔除记录，`clnd` 处理数据检查和去重。

## 清洗规则与设计选择

数据单元格先做 NFC 规范化和首尾空白处理，再进行缺失值与类型检查；缺失标记、枚举项和默认值采用相同处理，避免配置与数据比较不一致。表头和配置列名仍精确匹配。去重使用清洗后的值，剔除记录保留原始字段。

必填缺失或字段非法时剔除整条记录，可选字段可以留空或填入固定默认值；只有有效记录才占用去重键。金额继续使用 `Decimal`，转换和范围比较共用解析结果，避免引入浮点误差。

输出仍先写入临时目录再重命名，防止普通写入错误留下半套文件，清理由标准库负责。配置继续使用普通 JSON 解析，没有增加哈希或特殊解析钩子。

## 实际测试

在 `docs/ENVIRONMENT.md` 记录的本地环境中执行：

```console
python -m unittest discover -s tests -v
python scripts/verify.py --save docs/verification.json
```

31 项单元测试全部通过，包括 NFC 与去重、首尾空白、默认值、枚举和原始剔除字段检查；表头保持精确匹配。测试还检查数值精度和写入失败后的清理，重复运行的逐文件比较由复现脚本执行。

复现脚本的 5 次 CLI 调用通过，包含样例、重复运行、GB18030、严格模式失败和坏表头失败。样例输入 11 条，保留 4 条，剔除 6 条非法记录和 1 条重复记录，填补 2 个单元格；CSV 与原有预期结果一致。严格模式返回 1，坏表头返回 2，文件不存在返回 3 的检查也通过。

真实运行记录见 `unit-tests.txt` 和 `verification.json`，实际环境见 `ENVIRONMENT.md`。

## 局限

样例和边界输入都是合成数据，未做真实业务数据和大文件性能测试。编码需要明确指定；NFC 不负责忽略大小写或统一全半角。数据及去重集合保存在内存中，不适合直接处理超大文件。
