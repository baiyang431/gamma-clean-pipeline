# 实现与运行报告

## 实现思路

程序按“读取规则和数据、检查结构、逐条清洗、去重、输出”的顺序执行。JSON 规则与数据分开放置，修改必填列、数值范围或去重键时不需要改动程序。

`gamma_clean/__main__.py` 负责参数和退出码；`core.py` 中的 `load_schema` 检查配置，`convert` 转换字段，`clean_row` 处理一条记录，`clean_data` 解析 CSV 并去重，`run` 读写文件。数值使用标准库 `Decimal`，保留金额的小数精度。

先完成数据检查，再向临时目录写入三个结果文件，最后重命名为输出目录。这样可以避免普通写入错误留下不完整结果，临时目录由 `TemporaryDirectory` 自动清理。

## 主要清洗规则

单元格去除首尾空白，必填缺失或字段不合法时剔除整条记录；可选字段可以留空或填入固定默认值。重复比较发生在清洗和合法性检查之后，只保留第一条有效记录。详细参数和输出说明见 README。

样例保留字符串编号 `001`，将年龄 `020` 转为 `20`，金额 `001.2300` 转为 `1.23`，缺失城市填为“未知”。非法年龄、NaN 金额、无效日期、未知状态和缺失姓名写入剔除文件。

## 本次精简

去掉 NFC 转换、JSON 重复键和非有限常量的专用解析钩子，以及输入输出哈希。配置仍检查字段类型、范围和默认值，非有限数值边界仍会报错。JSON 重复键采用标准库行为，后出现的值覆盖前值。

枚举配置只检查列表和字符串类型，不再额外要求选项唯一或规范化。复现脚本直接比较文件内容，去掉哈希计算和额外的幂等实验；单元测试仍保留清洗结果再次输入的检查。输出文件名和样例 CSV 结果不变，`report.json` 不再提供 `sha256` 字段。

## 实际测试

在 `docs/ENVIRONMENT.md` 记录的本地环境中执行：

```console
python -m unittest discover -s tests -v
python scripts/verify.py --save docs/verification.json
```

单元测试结果见 `unit-tests.txt`，命令行运行结果见 `verification.json`。测试包含样例预期值、编码、缺失处理、去重、数值和日期边界、格式错误、文件不存在、退出码、输出保护及模拟写入失败。

本次本地运行的 31 项单元测试全部通过，复现脚本正常结束。样例输入 11 条，保留 4 条，剔除 6 条非法记录和 1 条重复记录，输出中填补了 2 个缺失单元格。清洗 CSV 与已有预期文件字节一致，两次运行的三个结果文件也相同。严格模式返回 1，坏表头返回 2；文件不存在返回 3 的行为由单元测试检查。

复现脚本实际运行样例、重复运行、GB18030 转码、严格模式失败和坏表头失败，并检查输出内容、源文件是否改变以及失败时是否生成输出目录。

## 局限

样例和边界输入都是合成数据，没有做真实业务数据和大文件性能测试。编码需要明确指定；字符串只去首尾空白，不合并视觉相同但编码不同的字符。数据及去重集合保存在内存中，不适合直接处理超大文件。
