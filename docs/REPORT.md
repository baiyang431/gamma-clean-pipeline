# 实现与验证报告

## 1. 目标与证据边界

本工程针对已提供的题目摘要，实现可重复运行的 Python 命令行 CSV 清洗，覆盖编码、缺失、重复、非法值、小型测试、输入输出样例、失败退出、README 和环境说明。

原题完整页面、讨论页及指定目标库没有可访问资料。因此本报告仅说明已实现并实际验证的内容，不宣称已取得题目评分、已满足未提供的附加规则或已通过远端 CI。

## 2. 实现

入口为 `gamma_clean/__main__.py`，核心位于 `gamma_clean/core.py`。规则由 JSON 声明，版本固定为 1；样例业务规则与源数据单独存放在 `examples/`。

处理顺序为：配置校验 → 严格解码 → CSV 结构检查 → NFC 与首尾空白处理 → 缺失值处理 → 类型及约束校验 → 有效记录去重 → 暂存并发布结果。

没有引入调度框架、数据库、插件系统或额外运行依赖。实际使用的标准库分别承担：`csv` 解析和导出，`json` 配置和审计，`decimal` 数值转换，`unicodedata` 规范化，`hashlib` 证据哈希，`argparse` 参数与帮助，`unittest` 测试，`tempfile/pathlib` 结果发布。

缺失填补仅使用明确声明的固定默认值，不根据测试数据统计估计。重复记录在清洗和合法性验证后判断，保留第一条有效记录，避免坏数据提前占用主键。

## 3. 端到端实测结果

命令：

```console
python -m gamma_clean --input examples/dirty.csv --schema examples/schema.json --output-dir results/demo
```

| 指标 | 实测值 |
| --- | --- |
| 输入数据记录 | 11 |
| 有效输出 | 4 |
| 非法记录 | 6 |
| 重复记录 | 1 |
| 剔除合计 | 7 |
| 有效输出中填补的单元格 | 2 |

守恒关系为 `11 = 4 + 6 + 1`。输出与人工预期 `examples/expected/clean.csv` 按字节相等。

非法记录覆盖年龄低于/高于边界、金额 NaN、不存在的日期、未知状态及空姓名。剔除文件保留原始字段和原因，例如 `age:below_min`、`amount:invalid_number`。示例记录号 3 为重复，5/6/7/8/9/11 为非法记录。

样例中编号 `001` 保留前导零；年龄 `020` 变为 `20`；`001.2300` 变为 `1.23`；`-0.000` 变为 `0`；可空年龄 `NA` 留空；两处缺失城市填为“未知”。

## 4. 正确性与边界验证

单元测试：

```console
python -m unittest discover -s tests -v
```

测试包含 31 个方法，覆盖：

- UTF-8 BOM、显式 GB18030、错误与未知编码、NUL 输入。
- 必填缺失、可选缺失、默认值校验、非法配置与重复 JSON 键。
- 整数格式、闭区间端点、超界值、长精度小数、负零、NaN、Infinity 和科学计数法拒绝。
- 闰年、非法日期、非 ISO 日期、枚举及 Unicode NFC 规范化。
- 清洗后去重、首个有效记录保留、无效记录不占键。
- 空文件、只有表头、列重排、缺列、多列、重复列、坏引号、空白记录、多行带引号字段。
- CLI 参数、版本、成功输出、严格失败、错误退出码、路径空格、已有输出保护、输入未修改。
- 模拟写报告时的磁盘错误，确认不发布半成品且清理暂存目录。

真实测试日志见 `unit-tests.txt`，真实 CLI 实测记录见 `verification.json`。测试用例数量不是评分推断，也不等于已穷尽所有边界。

## 5. 可复现与失败实验

`python scripts/verify.py` 实际启动 6 次 CLI：样例、重复运行、幂等、显式 GB18030、严格失败、坏表头失败。

| 实验 | 判据 | 本地结果 |
| --- | --- | --- |
| 重复运行 | 两个新目录中三个文件逐一 SHA-256 相同 | 通过 |
| 清洗幂等 | 清洗结果再次清洗，CSV 字节一致 | 通过 |
| 编码等价 | 合成样例转为 GB18030 并显式读取，干净 CSV 相同 | 通过 |
| 严格失败 | 样例含 7 条被剔除记录，退出 1，无输出目录 | 通过 |
| 结构失败 | 错误表头退出 2，无输出目录 | 通过 |
| 源文件保护 | 完成实验后，源文件 SHA-256 不变 | 通过 |

## 7. 限制与取舍

本次选择清晰、确定的规则，不自动猜测编码、日期或缺失值含义。这样会拒绝一些可被其他策略接受的数据，但处理方式明确且可复现。

仅支持有表头的单 CSV；内存消耗随文件大小及去重键数量增长。本次只做合成小数据的功能验证，没有大文件性能、真实业务分布或负载测试，因此不报告吞吐量和性能提升比例。

目录暂存和重命名用于避免正常失败发布半成品；没有实现断电恢复、跨进程发布锁和流式去重。默认非严格模式允许零条有效输出，若业务必须全部输入合法，应使用 `--strict` 并结合业务对空数据的要求验收。
