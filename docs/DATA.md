# 数据来源、许可、划分与版本

## 来源

`examples/dirty.csv` 是为本工程构造的合成测试数据，含 11 条逻辑数据记录与 7 个字段。姓名、编号、城市、金额、日期及状态的组合不对应任何实际个人、订单或业务采集记录。没有使用网络下载的数据集，也没有题目附件作为数据来源。

`examples/expected/clean.csv` 为按明示规则独立编写的预期结果，包含 4 条有效记录。测试同时检查各剔除记录的具体原因，避免仅用程序自己生成的输出验证自己。

测试中的 GB18030 输入由同一份 UTF-8 合成样例转码产生；Unicode、坏 CSV、极值和错误配置等边界输入在测试运行时临时构造。

## 许可

本仓库生成的源码、说明和合成样例按根目录 MIT License 提供。没有第三方数据许可需要继承。以后加入公开数据时，应单独记录下载地址、获取日期、明确许可和允许分享的范围，不能沿用当前“合成数据”的说明。

## 划分

| 材料 | 用途 | 规模 |
| --- | --- | --- |
| `dirty.csv` | 可读的端到端演示及回归验证 | 11 条数据记录 |
| `expected/clean.csv` | 人工预期基准 | 4 条数据记录 |
| `tests/test_pipeline.py` 动态输入 | 编码、缺失、去重、边界、结构和失败行为验证 | 31 个测试方法，部分含多组子用例 |
| `scripts/verify.py` 动态输入 | 实际 CLI、重复运行、幂等、编码及失败行为验证 | 6 次 CLI 调用 |

本项目没有训练统计模型，不设置机器学习训练集和测试集；以上是工程验证用途的划分。演示和回归复用同一份样例，不能据此宣称已证明对未知真实数据的泛化能力。

## 字段及处理依据

| 字段 | 类型与约束 | 缺失策略 |
| --- | --- | --- |
| id | 字符串、去重键、保留前导零 | 必填，缺失剔除 |
| name | 字符串 | 必填，缺失剔除 |
| age | 整数，闭区间 `[0,120]` | 可选，缺失留空 |
| city | 字符串 | 可选，缺失填“未知” |
| amount | 十进制数，`>=0` | 必填，缺失剔除 |
| joined | 有效 ISO 日期 | 必填，缺失剔除 |
| status | `active` 或 `inactive` | 必填，缺失剔除 |

这些是本工程演示所定义的规则，不是从原题截图推导出的业务要求。例如“年龄不超过 120”和“城市填未知”均为本项目选择。

## 版本

- 数据版本：`synthetic-v1`。
- JSON 规则格式版本：`1`，具体规则为 `examples/schema.json`。
- 程序版本：`1.0.0`。
- 代码精确版本通过 `git rev-parse HEAD` 获取，正式提交时以所提交仓库的 commit 为准。
- 输入、配置、清洗和剔除文件的 SHA-256 已实际计算并记录于 `verification.json` 的 `sample_report.sha256`。

CSV 文件统一由 `.gitattributes` 固定为 LF，避免 Windows 自动换行转换导致样例原始字节和哈希改变。
